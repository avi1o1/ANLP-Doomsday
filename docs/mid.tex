\begin{abstract}
Learned sparse retrieval, block-sparse attention and mixture-of-experts routing all
select items by a top-$k$ over inner products with learned features. Only
lexical retrieval corrects this score, through the inverse document frequency (IDF),
term-frequency saturation and length normalisation of BM25. Prior work disagrees on
whether the correction helps learned features. We ask when it helps and whether that can
be predicted without relevance labels. From one frozen multilingual encoder we build
fourteen sparse representations and score each under all eight combinations of the three
components on thirteen English and Indic collections. The full correction improves nDCG@10 in $90\%$ of primary rows, yet a
pre-registered predictor built on frequency diagnostics does no better than the majority
sign. In an exact Shapley decomposition, saturation, which uses no collection statistics,
accounts for $62\%$ of the gain. Its effect is set by the
dispersion of the stored feature values, a relation that holds on held-out parameter
settings in tests fixed in advance (Spearman $0.87$ and $0.90$). The contribution of IDF
and length normalisation depends on relevance, which no index statistic captures. In
exploratory analysis, agreement with a reference retriever predicts it on held-out
corpora ($R^2$ of $0.52$ to $0.66$). A decision rule built on this proxy improves mean
nDCG@10 by only $0.005$ over always applying collection statistics. KV-cache selection
and expert routing come next.
\end{abstract}

\section{Introduction}
\label{sec:intro}

A learned sparse retriever scores a query against a document by an inner product over a
vocabulary of non-negative features and returns the top $k$
\citep{formal2021splade,nguyen2023unified}. Quest does the same for the pages of a
key-value cache, scoring each page against the current query and attending only to the
best ones \citep{tang2024quest}. A mixture-of-experts router does it once more, scoring
every expert and sending the token to the top $k$ \citep{shazeer2017moe,fedus2022switch}.
These methods grew up in different communities. They share one computation
(Figure~\ref{fig:overview}).

Only retrieval learnt to correct the raw score in full. BM25 discounts features that occur
throughout the collection, stops rewarding repeated evidence past a point and adjusts
for document length \citep{sparckjones1972idf,robertson2009bm25}. Each part was designed
for words. Recent work applies BM25 to learned features and gets contradictory results.
On one benchmark suite BM25 beats the inner product by $0.20$ nDCG@10 on
sparse-autoencoder features and loses by $0.11$ on SPLADE-v3 \citep{clavie2026latent}.
The explanation offered is that BM25 helps while a vocabulary keeps a Zipfian frequency
curve \citep{clavie2026latent,han2026bm25v}. If that account is right, statistics of the
frequency curve should predict the sign of the gain before anyone runs the experiment.
Our proposal made that prediction the central test.

This report tells what happened when we ran it. We built fourteen sparse representations
from one frozen encoder and scored each under all eight combinations of the three
components on thirteen collections. The correction helped almost everywhere. The
predictor failed. Working out why it failed turned into the main finding so far. Most
of the gain comes from saturation, a component that reads no collection statistics at
all. Its effect is set by the stored values, while the value of the two collection-level
components depends on relevance. Section~\ref{sec:progress} follows the results in the order
they came.

\section{Problem Statement}
\label{sec:problem}

\paragraph{The correction.} For query and document vectors $x_q, x_d$ with
non-negative coordinates we score
\begin{equation}
S(q,d) = \sum_{j} x_{qj}\, w_j\, T(x_{dj}, \ell_d).
\label{eq:scorer}
\end{equation}
The weight $w_j$ is one or the smoothed inverse document frequency
$\idf_j = \ln(1 + (N - df_j + 0.5)/(df_j + 0.5))$, where $df_j$ of the $N$ documents have
feature $j$. The length factor $\ell_d$ is one or $1 - b + b L_d/\overline{L}$ with
$L_d = \sum_j x_{dj}$. The transform $T(f,\ell)$ is $f/\ell$ or the saturated
$(k_1+1)f/(f + k_1\ell)$. Each component is a switch, so a configuration is a bit string
$c \in \{0,1\}^3$ in the order IDF, saturation, length. Configuration \texttt{000} is
the plain inner product and \texttt{111} is BM25 \citep{robertson2009bm25}. IDF and
length normalisation read collection statistics. Saturation reads only the document.

\paragraph{The unit of observation.} Collection frequency belongs to a corpus, so one
row of the analysis pairs a representation with a collection at a support budget (the
query and document feature caps), BM25 parameters $(k_1, b)$ and a basis seed. Each row
carries eight nDCG@10 values $Q_c$, one per configuration.

\paragraph{What is predicted.} The pre-registered target is the margin
$m = (Q_{111} - Q_{000})/\operatorname{sd}(Q_{000}, \ldots, Q_{111})$, a standardised
effect on the same scale in every setting. Section~\ref{sec:progress} shows that $m$ is
poorly shaped for prediction, which led us to targets defined on the same eight values.
The Shapley value $\phi_s$ of switch $s$ is its marginal effect averaged over every order
in which the switches can be turned on \citep{shapley1953value}. Writing $Q_A$ for the
configuration with the switches in $A$ on,
\begin{equation}
\phi_s = \sum_{A \not\ni s}
\tfrac{|A|!\,(2-|A|)!}{6}\bigl(Q_{A\cup\{s\}} - Q_{A}\bigr).
\label{eq:shapley}
\end{equation}
The three values sum exactly to $Q_{111} - Q_{000}$. The collection gain
$G = Q_{111} - Q_{010}$ is the value of IDF and length normalisation once saturation is
applied. Its sign answers the practical question, whether to use collection statistics
for a given representation and collection. A predictor maps label-free quantities to
$m$, $\phi_s$ or $G$. We score it by sign accuracy against the majority sign and by
held-out $R^2$ and Spearman correlation. For $G$ we also measure the nDCG@10 reached when
collection statistics are used only where the prediction is positive.

\paragraph{Transfer.} Eq.~\eqref{eq:scorer} applies to any selection with a non-negative
score and a selection count. For KV page $i$ at decode step $t$, the feature value is the
softplus of the Quest criticality $r_{t,i}$. Its frequency $\sfreq_i$ is the fraction of
calibration queries for which the page enters the top-$k$ among the pages that exist at
that point. Its length is the norm of the page's concatenated key minima and maxima. For
expert $e$ at a token, the value is the router probability $p_e$, the frequency is the
share of calibration tokens routed to $e$ and the length is the norm of the router logits.
The selected experts are combined with their original gate weights, so the correction
changes only which experts run. In attention a row is a model, RULER task, context length
and token budget, scored by RULER accuracy \citep{hsieh2024ruler}. In routing a row is a model and task, scored
by negative token log-likelihood on WikiText and zero-shot MMLU accuracy. A predictor
fitted in retrieval is applied there without refitting. The registered criterion asks
for a sign accuracy of at least $70\%$ and a mean absolute error of at most $1.5$ times the
corpus-held-out RMSE in retrieval. In retrieval, always predicting a gain already reaches
$90\%$ sign accuracy. So before any transfer run we add a third condition. The predictor
must also beat the majority sign.

\section{Motivation and Research Gap}
\label{sec:motivation}

The three selectors take the raw match score at face value. None asks how often a
feature is selected across the collection, how evidence accumulates within an item or how
large the item is. Lexical retrieval asks all three questions. Its answers arrived one at
a time, as inverse document frequency \citep{sparckjones1972idf}, term-frequency
saturation \citep{robertson1994poisson} and pivoted length normalisation
\citep{singhal1996pivoted}, before BM25 combined them \citep{robertson2009bm25}. Inside
the transformer only fragments have reappeared. Loss-free balancing adds a per-expert bias
driven by recent load \citep{wang2024lossfree}, a frequency discount with no saturation or
length term. Streaming inference exempts the first keys of the cache from eviction
\citep{xiao2024streamingllm}.

Three papers have scored the same learned features with and without the correction, all
in retrieval. BM25 wins on sparse-autoencoder features of a dense retriever
\citep{clavie2026latent} and on SAE concept units \citep{park2025clsr}. It comes out level
on visual words \citep{han2026bm25v}. Two of these papers explain the pattern through the
Zipfian shape of the vocabulary. None of the three varies the vocabulary systematically
or asks which of the three components produces the gain. Their explanation has never been
turned into a quantity computed before the experiment. Nor has it been tested where
the same computation runs inside a model.

\section{Contributions}
\label{sec:contributions}

\begin{enumerate}
\item \textbf{A controlled grid.} Fourteen sparse representations from one frozen encoder,
scored under all eight configurations on thirteen collections, in 182 primary and
1{,}226 sensitivity rows.
\item \textbf{A negative result with its cause.} The pre-registered frequency predictor
does no better than the majority sign. We show why it could not have worked.
\item \textbf{An attribution of the gain.} Exact Shapley values assign $62\%$ of the gain
to saturation and about a tenth to IDF. A mechanism for saturation, fixed in advance,
passes its tests on held-out parameter settings.
\item \textbf{An exploratory label-free predictor} of the collection-level gain, built
from agreement with a reference retriever.
\item \textbf{Transfer adapters} for KV-page selection and expert routing, with
native-parity tests, ready for the frozen predictors.
\end{enumerate}

\section{Related Work}
\label{sec:related}

\paragraph{Term weighting.} IDF began as a statistical account of term specificity
\citep{sparckjones1972idf}. Saturation came from approximating the two-Poisson model of
within-document frequency \citep{robertson1994poisson}. Length normalisation was pivoted
so that long documents are neither favoured nor penalised \citep{singhal1996pivoted}.
BM25 combines the three \citep{robertson2009bm25}. Every part was motivated by the
statistics of words, which is why it is an open question whether any of them helps
features that are not words.

\paragraph{Retrieval scorers.} Dense retrievers score by the inner product of embeddings
\citep{karpukhin2020dpr}. Our encoder is multilingual E5 \citep{wang2024me5}. Learned
sparse retrieval keeps the inverted index and learns term weights, through contextual
exact match \citep{gao2021coil} or expansion over the subword vocabulary in SPLADE
\citep{formal2021splade,formal2021spladev2,lassance2024spladev3}. Two frameworks place
these methods side by side \citep{lin2021conceptual,nguyen2023unified}. Learned weights
also change the cost of query processing \citep{mackenzie2021wacky}, which is why we
record posting visits and index size. Every one of these methods scores by inner product.

\paragraph{Learned concept vocabularies.} Sparse autoencoders decompose dense activations
into many non-negative features \citep{cunningham2024sae}. Top-$K$ SAEs fix the number
active per input \citep{gao2025topksae}. CL-SR indexes SAE-decomposed embeddings as
concept units weighted by IDF. Dropping that weighting costs 11 to 18 percent of its
nDCG@10 on TREC-DL \citep{park2025clsr}, the one published ablation of the correction.
SPLARE trains an SAE-based sparse retriever \citep{formal2026splare}. SAE-SPLADE replaces
the language-model head of SPLADE with an SAE \citep{zong2026tokens}. Both score by inner
product. Quantised codes offer a second route to a discrete vocabulary, through product
quantisation \citep{jegou2011pq}, residual quantisation \citep{chen2010rq} and their GPU
implementations \citep{johnson2021faiss}.

\paragraph{BM25 on learned features.} \citet{clavie2026latent} show that SAE features of a
frozen dense retriever have roughly Zipfian collection statistics and can be scored by
BM25 directly. In their Appendix~C, BM25 reaches $0.582$ nDCG@10 against $0.381$ for the
inner product on SAE latent terms. On SPLADE-v3 the order flips, $0.455$ against $0.568$.
\citet{han2026bm25v} find the two scorers within about two points of R@1 on image
retrieval. They credit the parity to top-$k$ filtering, which already suppresses what IDF
would down-weight. When they raise the per-patch budget from $16$ to $128$, document
frequencies converge and R@1 falls from $0.508$ to $0.038$.

\paragraph{Predicting effectiveness without labels.} Query performance prediction
estimates retrieval quality from the query and the ranking alone
\citep{carmel2010difficulty}. One family of methods measures the divergence of the
retrieved language model from the collection \citep{cronen2002clarity}. Another reads the
spread of the top retrieval scores \citep{shtok2012nqc}. Retrieval systems can also be
ranked without judgements against pseudo-relevant documents drawn from pooled output
\citep{soboroff2001ranking}. Our label-free predictor borrows both ideas for a new target,
the difference between two scorers.

\paragraph{Attributing an effect to components.} The Shapley value
\citep{shapley1953value}, familiar from SHAP \citep{lundberg2017shap}, is exact over a
complete $2^3$ factorial and needs no sampling.

\paragraph{Selection inside the transformer.} Quest scores KV pages against page min-max
key summaries \citep{tang2024quest}. H2O keeps recent and heavy-hitter tokens
\citep{zhang2023h2o}. SnapKV keeps the positions an observation window attends to
\citep{li2024snapkv}. StreamingLLM keeps the first keys as attention sinks
\citep{xiao2024streamingllm}. Expected Attention prunes pairs that future queries are
predicted to ignore \citep{devoto2025expectedattention}. Massive activations single out a
few positions by magnitude \citep{sun2024massive}. None of these uses the rate at which an
entry is selected across queries.

\paragraph{Expert routing.} Sparse mixture-of-experts layers route each token to its top-$k$
experts \citep{shazeer2017moe,lepikhin2021gshard,fedus2022switch}. Balance comes from an
auxiliary loss \citep{zoph2022stmoe} or from a load-driven bias \citep{wang2024lossfree}.
DeepSeekMoE splits experts more finely and adds shared experts \citep{dai2024deepseekmoe}.
\citet{su2026superexperts} find a handful of experts, identified by activation magnitude,
whose removal degrades the model badly. We use OLMoE \citep{muennighoff2025olmoe}, which
activates 8 of 64 experts per layer. To our knowledge no work treats retrieval scoring,
KV selection and routing as one scoring problem.

\paragraph{Viability.} Every piece of the study already existed, from cheap sparse codes
to label-free quality proxies. What was missing was the controlled comparison, whose
retrieval half is now complete.

\section{Method}
\label{sec:method}

\paragraph{Representations.} Holding the encoder fixed lets us vary only the vocabulary.
All representations come from \texttt{multilingual-e5-base} \citep{wang2024me5} at a
pinned revision. Seven bases are fitted on the same $200{,}000$ MS~MARCO passages
\citep{bajaj2016msmarco} and nowhere else. They are split-rectified identity, Gaussian
projection (768), PCA (384), soft $k$-means over $4{,}096$ centroids, product and residual
quantisation ($8 \times 256$) and a Top-$K$ SAE with $8{,}192$ features of which at most 32
are active. Pooled granularity applies each basis to the mean of the content token
states. Token granularity applies it to each state before summing. This gives fourteen
representations. A secondary SAE shares one dictionary across both granularities to
separate aggregation from fitting. SPLADE has its own backbone, so it stays outside the
grid as an external comparison.

\paragraph{Corpus statistics.} Supports are capped before any statistic is computed, at
32 query and 128 document features in the primary budget. Document frequency, lengths and
IDF come from the capped vectors of each target corpus. Retrieval is exact over the whole
corpus. The primary grid uses $k_1 = 1.2$ and $b = 0.75$. For a linear map $C$
and diagonal weights $D$, weighted scoring $q^\top C^\top D C d$ preserves every ranking of
the inner product when $C^\top D C = \alpha I$ with $\alpha > 0$. Rectification, truncation, saturation and
length normalisation are non-linear, so no representation here meets that condition.

\paragraph{Collections.} The thirteen collections come from eleven corpora. MS~MARCO dev,
TREC-DL 2019 and TREC-DL 2020 share one set of documents. The others are six BEIR sets
\citep{thakur2021beir}, LIMIT \citep{weller2025limit} and the Hindi, Bengali and Telugu
portions of MIRACL \citep{zhang2023miracl}, each evaluated within its language. LIMIT is
built so that the top-$k$ sets its queries need exceed what a low-dimensional embedding can
represent.

\paragraph{Experiment families.} The primary family covers all thirteen collections
(Table~\ref{tab:families}). Each sensitivity family varies one setting at a time on the ten
collections outside MS~MARCO.

\paragraph{Significance.} A paired bootstrap over queries with $10{,}000$ draws recomputes
numerator and denominator. Holm correction \citep{holm1979} runs within each pre-declared
family, the all-on against all-off comparison and the three component main effects.
Significance is reported on the ten collections outside MS~MARCO.

\paragraph{Diagnostics.} No feature describing a row reads relevance labels. The six
pre-registered frequency diagnostics are the active fraction, the Zipf slope of the
feature-frequency curve, the Gini coefficient of activation mass, frequency and
activation mass in the most frequent $1\%$ of features and IDF variance. The primary ridge
model uses the slope, IDF variance and frequent activation share. Index statistics
describe the stored values, chiefly $\mathrm{cv}_x$, the coefficient of variation of the
stored document values. Ranking features come from the stored top-100 list $R_c(q)$ of
every configuration $c$ and query $q$. They measure how much each switch changes the top 10
and the shape of the top-100 scores \citep{shtok2012nqc}. The pseudo-quality $\tilde{Q}_c$
is the mean nDCG@10 of $R_c(q)$ when the top 10 of a reference retriever on the same query
is taken as relevant. The references are text BM25, the dense encoder and the two fused by
reciprocal rank. Putting $\tilde{Q}_c$ in place of $Q_c$ in Eq.~\eqref{eq:shapley} and in
$G$ gives pseudo-label estimates $\tilde{\phi}_s$ and $\tilde{G}$ with no fitted parameter.

\paragraph{Validation.} Predictors are ridge regressions with the scaler and penalty chosen
inside training folds. Folds hold out a whole basis family (linear, clustered, quantised,
learned) or a whole corpus, reported separately. A fit on primary rows is also scored on
the rows at other $k_1$ and $b$, which share collections with it.

\paragraph{Transfer adapters.} The attention adapter implements Quest-style criticality
over sixteen-token pages with dense prefill and sparse decode. It counts how often each
page enters the top-$k$ over causal prefill positions and applies Eq.~\eqref{eq:scorer}
with pages for documents. The routing adapter applies the correction to OLMoE router
probabilities for selection and combines with the original gate weights. In both, the
all-off configuration calls the native code path. Six tests confirm exact native parity,
causal calibration, budget charging including sink pages and the gate mixture.

Under the plain inner product the capped sparse codes are close to useless on every

hint of trouble for the predictor.

\subsection{The pre-registered predictor fails}

The margin was meant to be predicted from the shape of the frequency curve, and it could
not be. The primary ridge model explains almost none of the held-out variance, with $R^2$ of
$0.04$ across basis families and $0.02$ across corpora. Its sign accuracy is exactly that
of always predicting a gain. A variant with all six diagnostics is not consistently better. By the
criterion we registered, the frequency diagnostics carry no usable information about the
margin.

Part of the failure lies in the target. Most margins fall between $1.5$ and $3.5$, because
the margin mostly records that the uncorrected scorer is broken. That leaves little
variation for any diagnostic to explain. The rest of the failure lies in what the
correction is made of.

To see what a predictor would need to capture, we split each row's gain among the three
switches with Eq.~\eqref{eq:shapley}. Saturation carries most of the gain on every set of
rows (Table~\ref{tab:shapley}). IDF, the component the Zipfian account is
about, carries the least at the primary budget. Reading down the budget rows, the share of
IDF shrinks as supports grow while the share of length grows. At native support IDF's
share is slightly negative. \citet{han2026bm25v} report the same trend for image
features. The Holm-corrected main effects agree, with saturation significant most often
and IDF least often.

IDF is not empty, though. With shuffled document frequencies its mean Shapley value turns
negative. The real value is larger in $83\%$ of rows (one-sided Wilcoxon
$p < 10^{-6}$). Uniform frequencies, which remove IDF altogether, leave all-on quality no
lower. The frequencies carry information, but little of it reaches nDCG@10.

\subsection{Why saturation can be predicted and the rest cannot}
\label{sec:predicts}

Across representations, the contribution of saturation rises with $\mathrm{cv}_x$, the
coefficient of variation of the stored values (Table~\ref{tab:bases}). This follows from
the form of the transform. With length normalisation off, saturation maps a stored value $f$ to
$g(f) = (k_1+1)f/(f+k_1)$. The ratio $g(f)/f$ falls as $f$ grows, so saturation shrinks
large values relative to small ones. If every stored value were equal, $g$ would rescale
all scores alike and change no ranking. The more unequal the values, the more the ranking
moves. A smaller $k_1$ bends $g$ harder. Pooled PQ and RQ are the limiting case. They store
equal values with equal lengths, so their saturation and length effects are exactly zero
in every one of their rows. Outside these two codes saturation almost always helps. How
much it moves the ranking is a property of the index.

IDF and length normalisation behave differently. They too move the ranking by an amount
the index fixes. Whether the move helps depends on whether heavy documents were
over-rewarded relative to their relevance and whether rare features separate relevant
documents from the rest. Both questions involve relevance, which no statistic of the index
records. This is why a predictor built on the frequency curve could not tell when
collection statistics help. The decision matters most for strong representations.
Collection statistics supply most of the gain for the weak pooled linear codes, but for
token-level SAE and PCA they help after saturation on fewer than half the collections
(Table~\ref{tab:bases}).

If the missing ingredient is relevance, a proxy for relevance should restore the
prediction. Everything in this subsection came after the confirmatory tests were fixed
and is exploratory. We scored every configuration against a reference retriever's top 10,
treated as relevant. Table~\ref{tab:predictor} compares three tiers of features. The
frequency diagnostics barely predict any target. Index statistics predict saturation and
little else. Only the pseudo-label tier reaches positive held-out $R^2$ on every target
and every axis. Every target is a fixed linear combination of the
eight $Q_c$, so a pseudo-quality that orders the configurations like the true one yields
correlated targets. It does, with a median within-row Spearman correlation of $0.98$.

The practical test is a decision rule with no fitted parameter, which uses collection
statistics only where $\tilde{G}$ is positive. It raises mean nDCG@10 from $0.143$ (always
using them) to $0.148$, against $0.151$ for an oracle. That recovers $61\%$ of a headroom
below $0.01$. The gain holds at other budgets and parameters. Across seeds its interval
reaches zero. The gains are small because always using collection statistics is already
close to the oracle on most rows. We also chose the rule during the exploration.

The references carry biases of their own. The correction under study is BM25 applied to
other features, so agreement with text BM25 may reward configurations for behaving like
BM25. Lexical systems also contributed to the judgement pools of several collections. The
dense reference errs the other way. The sparse codes come from the same encoder, so
agreement with it partly measures how much of the embedding a configuration keeps. The
prediction of $G$ holds with either reference (Table~\ref{tab:predictor}). Neither
reference is free of bias, so the result stays exploratory until it is tested on data
fixed in advance.

\section{Remaining Plan}
\label{sec:plan}

The retrieval half of the project leaves two predictors to carry into the transformer.
One is the pre-registered predictor, which goes to attention and routing as registered.
The other is the pseudo-label predictor, which needs a label-free reference native to each
setting. For KV pages that reference is exact attention mass. For routing it is the dense
softmax mixture over all experts. Both come from the uncorrected model. Both predictors and
the thresholds will be frozen before any corrected outcome is seen. Each result will be
reported against the majority sign as well as the registered thresholds. Table~\ref{tab:plan} gives the schedule. Anirudh Sankar writes and
runs the experiment code. Mohit Kumar Singh analyses the results and owns the
pre-registrations. Arihant Tripathy writes the report and relates the results to the
literature. Aviral Gupta, who proposed the idea, makes the presentations.

\section{Limitations}
\label{sec:limitations}

One encoder underlies every representation, so basis and encoder effects are not
separable. E5 saw MIRACL in training, so the Indic results say nothing about unseen
languages. The sparse codes are far weaker than their encoder, so the attribution may not
hold for strong retrievers such as SPLADE. The label-free predictor needs queries and a
second retriever run. Routing is tested only at inference.
